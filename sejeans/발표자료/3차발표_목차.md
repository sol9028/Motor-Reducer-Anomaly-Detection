## [슬라이드 2] 프로젝트 배경

**타이틀**: 왜 이 문제를 풀어야 하는가?

**내용 (3개 포인트):**
- 전기차(EV) 보급 확대 → 모터·배터리 고장 조기 탐지 필요성 증가
- 기존 방식: 클라우드 전송 후 분석 → 실시간 대응 불가, 통신 비용 발생
- 목표: **차량 내 엣지 디바이스**에서 경량 ML 모델로 실시간 이상 탐지

**분류 대상 (표 또는 아이콘 2개):**

| 구성요소 | 분류 클래스 | 데이터 형식 |
|---|---|---|
| 모터-감속기 | NORMAL / ECC10 / ECC20 / DEMAG / REDUC | PNG (STFT 스펙트로그램) |
| 배터리 | NORMAL / 셀전압 결함 / 셀편차 결함 | NPY (수치 행렬) |

**데이터 출처**: AI-Hub 제공, 차종 IONIQ·KONA·NIRO, 총 550,800개 샘플 (600GB)

## [슬라이드 3] 지난 발표(2차) 요약 도식

**타이틀**: 2차 발표에서 한 것 — Pilot Test

**도식 (가로 흐름 화살표):**

```
샘플 PNG 데이터
(AI-Hub 제공, 225개)
     ↓
[1] 데이터 경량화
PNG(2000×1280) → CSV (4피처: peak_freq_bin, band_start, band_end, rms)
약 12배 용량 감소 (15.5MB → 1.3MB)
     ↓
[2] 모델 선택
MiniRocket (시계열 변환) + Logistic Regression (분류)
센서별 3개 모델 (Current_U / Vib_Motor / Vib_TM)
     ↓
[3] 데이터 누수 방지
같은 CSV에서 나온 청크 → 동일 group_key 부여
→ GroupShuffleSplit으로 train/val 완전 분리
     ↓
[4] 대시보드 구현
Anomaly Score = 1 − P(NORMAL)
통합점수 = 60%×평균 + 40%×최고
경고 기준: AS<0.3 정상 / 0.3~0.7 주의 / ≥0.7 경고
```

**결론 박스**: "파이프라인 전 과정 동작 확인 완료 → 본 데이터로 확장"

> 🖼️ **[이미지 자리 — 비워둘 것]** 2차 발표 대시보드 스크린샷 (Anomaly Score 게이지 화면, 우측 배치)

## [슬라이드 6] 기준 모델 학습 및 평가 결과

**타이틀**: 기준 모델 — 센서별 9슬롯 학습 결과

**학습 구조 (도식):**
- 차종 3 × 센서 3 = **9개 슬롯** 각각 독립 모델

## [슬라이드 7] 개선 1 — 학습 속도 15배 향상

**타이틀**: 개선 1 — 28시간 → 1시간 52분

**3가지 개선 (아이콘+설명):**

1. **솔버 교체 (saga → lbfgs)**
   - ConvergenceWarning 원인이 saga의 느린 수렴
   - lbfgs: L2 정규화 + 고차원 피처에서 훨씬 빠른 수렴

2. **MiniRocket 변환 결과 캐싱 (.npz)**
   - 입력 데이터 해시값을 키로 캐싱
   - 분류기 설정 변경 시 무거운 변환 단계 스킵
   - 재실험 수십 분 단위로 단축

3. **슬롯 병렬 학습 (3개씩 병렬)**
   - MiniRocket 내부 병렬은 n_jobs=1로 제한
   - 바깥 병렬과 안쪽 병렬의 코어 중복 점유(oversubscription) 방지

**결과 (강조 박스):**

| | 학습 시간 | macro-F1 |
|---|---|---|
| 기준 모델 | 약 28시간 | 0.63~0.67 |
| 속도 개선 후 | **1시간 52분** | **동일** (정확도 손실 없음) |

**→ 약 15배 속도 향상**

> 🖼️ **[이미지 자리 — 비워둘 것]** 학습 시간 비교 막대 그래프 (28h vs 1h52m 시각적 대비)

## [슬라이드 8] 개선 2 — 12채널 융합으로 성능 향상

**타이틀**: 개선 2 — Late Fusion → Early Fusion (12채널)

**왼쪽: 기존 방식의 한계 (late fusion)**
- 센서별 따로 예측 후 확률 합산
- 센서 간 결합 패턴 활용 불가
- ex) DEMAG는 진동+전류 조합으로만 구별 가능한 경우 존재

**오른쪽: 개선 방식 (early fusion)**
- 3개 센서(각 4피처) → **12채널**로 한 번에 입력
- MiniRocketMultivariate는 채널 수 무관하게 동작 → 코드 변경 최소

**융합 가능성 검증:**
- 전체 12,720개 세션에서 3개 센서 모두 존재 (누락 0건)
- 센서별 길이 190,000행으로 동일 → 손실 없는 융합 확인

> 🖼️ **[이미지 자리 — 비워둘 것]** Late Fusion vs Early Fusion 구조 비교 도식 (센서별 따로 → 12채널 하나로 묶는 흐름)

**결과 표:**

| 차종 | Late Fusion (센서별 평균) | Early Fusion (12채널) | 향상폭 |
|---|---|---|---|
| IONIQ | 0.657 | **0.871** | +0.214 |
| KONA | 0.673 | **0.874** | +0.202 |
| NIRO | 0.628 | **0.826** | +0.198 |

## [슬라이드 9] 혼동행렬 분석

**타이틀**: 혼동행렬로 본 센서별·모델별 성능 차이

**도식 설명 (그림 1 삽입 - 보고서의 혼동행렬 이미지):**

> 🖼️ **[이미지 자리 — 비워둘 것]** 혼동행렬 그리드 이미지 (보고서 그림 1: 차종×센서 구성, 맨 오른쪽이 ★12채널 융합 결과) — 슬라이드 중앙에 크게 배치

행: 차종 (IONIQ / KONA / NIRO)
열: 센서 (Current_U / Vib_Motor / Vib_TM / ★12채널 융합)
대각선 = 정답

**3가지 핵심 관찰 (아이콘+텍스트):**

1. **전류 센서(Current_U)**: 대각선 흐릿, DEMAG·ECC10·ECC20 혼동 심함
   - IONIQ에서 실제 DEMAG → ECC10 659건, ECC20 726건으로 누출
   
2. **진동 센서(Vib_Motor·Vib_TM)**: ECC10·ECC20·REDUC는 잘 맞히나
   - **DEMAG ↔ NORMAL 혼동** 심각 (IONIQ Vib_TM: 각각 ~1,800건 뒤섞임)
   
3. **12채널 융합 모델(★12sum)**: 대각선 뚜렷
   - DEMAG→NORMAL 오분류: ~1,800건 → 873건 (절반 이하)
   - **잔여 과제**: DEMAG↔NORMAL은 여전히 가장 큰 오류 (자석 열화의 특성)

## [슬라이드 11] 2학기 계획

**타이틀**: 남은 과제와 2학기 계획

**3개 트랙 (아이콘+설명):**

### 트랙 1. DEMAG↔NORMAL 오분류 문제 해결
- 피처 보강: 고조파 대역 에너지 비율, 스펙트럼 엔트로피 등 세밀한 피처 추가
- 2단계 분류기: 1단계(NORMAL vs 이상) → 2단계(DEMAG 전용 이진 분류기)
- 결정 임계값·클래스 가중치 조정
- 오분류 샘플 직접 분석 (어떤 운전 조건에서 오류가 집중되는지)

### 트랙 2. 메타데이터 활용
- 활용 데이터: 토크(명령/실제), 모터 회전속도(rpm), 인버터·모터 온도
- 운전 조건 정규화: rpm·토크로 신호 정규화 → DEMAG 미세 신호 선명화
- 토크 추종 오차(reference − actual): 감속기 기어 결함(REDUC) 단서
- 온도 패턴: DEMAG 시 발열 패턴 차이 활용 가능

### 트랙 3. 배터리 이상 탐지 시작
- 대상: NPY 수치 행렬 (셀 96/98개 전압·편차), 3클래스 분류
- 방법: 모터-감속기에서 검증한 경량 파이프라인 그대로 이식
- 셀전압 결함: 개별 셀 min/max, 임계 초과 셀 수
- 셀편차 결함: 셀 간 전압 표준편차, 최대–최소 편차
- 모듈 위치 추정: 셀→모듈 매핑으로 이상 위치 표시
