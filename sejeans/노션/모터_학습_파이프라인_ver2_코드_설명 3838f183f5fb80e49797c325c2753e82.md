# 모터-감속기 학습 파이프라인 — 코드 설명서

이 문서는 **코드를 한 줄도 읽지 않아도** 이 노트북(`모터_학습_파이프라인.ipynb`)이 무엇을, 왜, 어떻게 하는지 이해할 수 있도록 작성한 설명서다.

---

## 1. 한눈에 보기

이 노트북은 모터-감속기 센서 데이터를 보고 **지금 부품이 어떤 상태인지 5가지 중 하나로 맞히는 모델**을 학습한다.

맞히는 5가지 상태는 다음과 같다.

- **NORMAL** — 정상
- **ECC10** — 편심 주의
- **ECC20** — 편심 결함
- **DEMAG** — 자석 성능 저하(감자)
- **REDUC** — 감속기 기어 결함

학습이 끝나면 **상태를 판정하는 모델 묶음**(`model_registry.joblib`)과 **그 모델이 얼마나 잘 맞히는지 채점표**(`eval_results.json`)가 저장된다. 이 모델 묶음을 대시보드에 연결하면 실시간 이상 탐지 데모가 돌아간다.

---

## 2. 입력과 출력

| 구분 | 내용 |
| --- | --- |
| **입력** | 4개 핵심 특징(`peak_freq`, `band_start`, `band_end`, `rms`)이 시간순으로 들어 있는 CSV 파일들 (이전 단계에서 PNG 스펙트로그램을 변환해 만든 것) |
| **출력** | ① `model_registry.joblib` — 학습된 모델 묶음 ② `eval_results.json` — 슬롯별 성능 채점표 |

> 이 노트북은 PNG→CSV 변환(Stage 1)이 **이미 끝난 상태**를 전제로 한다. 즉 “CSV가 들어오면 모델을 만든다”가 이 노트북의 역할이다.
>

## 3. 먼저 알아야 할 5가지 개념 (쉬운 비유)

### ① 슬롯 (slot) — “전문가를 따로 둔다”

차종(IONIQ·KONA·NIRO)과 센서(전류·모터진동·감속기진동)마다 신호 모양이 다르다. 그래서 **하나의 만능 모델**로 뭉뚱그리지 않고, **(차종 × 센서) 조합마다 전문가 모델을 따로** 만든다. 최대 3차종 × 3센서 = **9개 전문가 모델**이 생긴다. 이 한 칸을 “슬롯”이라 부른다.

### ② 청크 (chunk) — “긴 녹음을 한 입 크기로 자른다”

센서 데이터는 길게 이어진 시계열이다. 모델은 너무 긴 데이터를 한 번에 못 먹으니, **2000행씩 잘라 일정한 크기의 조각**으로 만든다. 이 조각 하나가 모델이 먹는 **샘플 1개**다. 참고로 2000행은 **원본 PNG 약 1장 분량**이라, “청크 개수 ≈ PNG 개수”로 보면 된다.

### ③ group_key — “�닝(데이터 누수) 방지용 출석번호”

같은 녹음에서 잘라낸 청크들은 사실상 똑같은 신호다. 이걸 한쪽은 공부자료(학습), 한쪽은 시험문제(검증)로 나눠 쓰면 **답안지를 보고 시험 보는 셈**이 되어 성능이 거짓으로 부풀려진다. 그래서 **같은 녹음에서 나온 청크에는 같은 출석번호(group_key)**를 붙이고, 한 출석번호는 통째로 학습 또는 검증 **한쪽에만** 들어가도록 강제한다.

### ④ MiniRocket + 로지스틱 회귀 — “지문 스캐너 + 판별기”

- **MiniRocket**: 시계열 청크를 **숫자 특징 다발(약 1만 개)**로 빠르게 바꿔주는 변환기다. 비유하면 시계열의 “지문을 스캔”하는 장치다. 무겁고 느린 딥러닝 대신 쓰는, 가볍고 매우 빠른 방법이다.
- **로지스틱 회귀(LogisticRegression)**: 그 지문(특징 다발)을 보고 **5가지 상태 중 무엇인지 확률로 찍는** 단순하고 빠른 판별기다.

### ⑤ 교차검증 (StratifiedGroupKFold) — “돌아가며 모의고사 3번”

데이터를 3등분해서, 2/3로 공부하고 1/3로 시험 보기를 **자리를 바꿔가며 3번** 반복한다. 이렇게 하면 “운 좋게 한 번 잘 본 것”이 아니라 **평균 실력**을 알 수 있다. 이때 ③의 출석번호 규칙(같은 녹음 안 섞기)과 클래스 비율 유지를 동시에 지켜준다.

## 4. 전체 동작 흐름 (노트북 위→아래 순서)

1. **환경 설정** — 필요한 라이브러리(sktime)를 깔고 구글 드라이브를 연결한다.
2. **경로 · 파라미터 설정** — CSV가 있는 폴더(`CSV_ROOT`)와 결과 저장 폴더(`MODEL_DIR`) **두 곳만** 채우면 된다. 나머지 설정값은 기본값으로 충분하다.
3. **데이터 스캔 · 청킹 준비** — 모든 CSV를 훑어 (차종, 센서) 슬롯으로 분류하고, 청크로 자르는 도구를 준비한다.
4. **슬롯 점검** — 어떤 슬롯이 학습 가능한지 표로 출력한다. *상태가 1종류뿐인 슬롯은 분류가 불가능하므로 자동 제외*된다.
5. **모델 정의** — 청크 캡 → MiniRocket 변환 → 로지스틱 회귀로 이어지는 학습 부품을 정의한다.
6. **전체 학습 실행** — 9개 슬롯을 차례로 학습해 모델 묶음을 만들고 저장한다. *슬롯 하나가 끝날 때마다 중간 저장*하므로, 중간에 끊겨도 그때까지의 결과는 남는다.
7. **성능 채점** — 슬롯별로 얼마나 잘 맞혔는지(macro-F1, 정확도, 혼동행렬)를 표와 그림으로 보여준다.
8. **예측 데모** — 저장된 모델로 몇 개를 예측해 **이상 점수(Anomaly Score)**를 확인한다.
    - **이상 점수 = 1 − (정상일 확률)** → 값이 클수록 “비정상 의심”이 크다는 뜻이다.

## 5. 이번 버전에서 “빨라진” 이유

대용량(약 60만 청크)으로 돌리면 예전 구조는 몇 시간이 걸리거나 메모리가 터질 수 있었다. 이번 수정으로 다음 세 가지를 개선했다.

1. **중복 청크 줄이기 (가장 큰 효과)**
같은 녹음에서 나온 청크들은 신호가 거의 똑같아 전부 학습할 필요가 없다. **슬롯·클래스당 최대 4000개**(`CHUNK_CAP_PER_CLASS`)로 제한해, 정확도는 거의 그대로 두면서 데이터 양과 학습 시간을 크게 줄였다.
2. **무거운 변환은 한 번만**
예전에는 교차검증 3번 + 최종학습마다 MiniRocket 변환을 **슬롯당 4번** 반복했다. 이제는 **슬롯당 1번만** 변환해 그 결과를 재사용하고, 가벼운 로지스틱 회귀만 매번 다시 학습한다. → 변환 비용 약 4배 절감.
3. **판별기 비용 절감**
로지스틱 회귀의 최대 반복수를 현실적인 값(`LR_MAX_ITER=300`)으로 낮췄다. 표준화된 특징에서는 보통 이 안에서 충분히 수렴한다.

추가로, **슬롯마다 중간 저장(체크포인트)**을 넣어 Colab 세션이 끊겨도 그때까지 학습된 모델은 보존된다.

## 6. 손대도 되는 설정값 (파라미터)

대부분 기본값 그대로 쓰면 된다. 속도·메모리가 문제일 때만 아래를 조절한다.

| 설정값 | 기본값 | 언제 바꾸나 |
| --- | --- | --- |
| `CSV_ROOT` | (비어 있음) | **필수** — 입력 CSV가 있는 폴더 경로 |
| `MODEL_DIR` | (비어 있음) | **필수** — 결과를 저장할 폴더 경로 |
| `CHUNK_CAP_PER_CLASS` | `4000` | 더 빠르게: 값을 낮춘다 / 정확도를 더 끌어올리고 싶다: 값을 올린다(`None`이면 제한 없음) |
| `NUM_KERNELS` | `10000` | 너무 느리거나 메모리가 부족하면 `5000`으로 낮춘다 |
| `LR_MAX_ITER` | `300` | “수렴하지 않았다”는 경고가 뜨면 `1000`으로 올린다 |
| `MINIROCKET_N_JOBS` | `-1` | `-1`은 전체 CPU 코어 사용. 보통 그대로 둔다 |
| `LR_CLASS_WEIGHT` | `None` | 특정 슬롯에서 클래스가 심하게 치우쳤을 때만 `"balanced"`로 켠다 (PNG가 균형이라 평소엔 불필요) |
| `N_SPLITS` | `3` | 교차검증 횟수. 그대로 권장 |

2. **경로 & 파라미터** 셀에서 `CSV_ROOT`와 `MODEL_DIR` 두 줄만 채우기.
3. 위에서 아래로 모든 셀을 순서대로 실행.

> **요령**: 전체를 한 번에 돌리기 전에, 슬롯 하나만 먼저 돌려 걸리는 시간을 재보고 거기에 슬롯 수(최대 9)를 곱하면 전체 소요 시간을 가늠할 수 있다.

## 8. 결과 읽는 법

- **`model_registry.joblib`** — `(차종, 센서)`별 모델이 들어 있는 묶음. 대시보드/예측에서 이 파일을 불러 쓴다.
- **`eval_results.json`** — 슬롯별 채점표. 핵심 숫자는 **macro-F1**이다.
    - macro-F1은 5개 상태를 **고루 잘 맞혔는지**를 0~1로 나타낸 점수다(1에 가까울수록 좋음). 단순 정확도와 달리, 수가 적은 상태를 못 맞히면 점수가 확 떨어지므로 **균형 잡힌 실력**을 본다.
    - 함께 나오는 **혼동행렬(confusion matrix)**은 “어떤 상태를 어떤 상태로 헷갈렸는지”를 표로 보여준다.

## 9. 알아두면 좋은 트레이드오프

- **청크 캡**은 데이터 일부만 사용한다. 같은 녹음의 청크는 거의 동일하므로 정확도 손실은 보통 미미하지만, 성능을 끝까지 짜내야 한다면 `CHUNK_CAP_PER_CLASS`를 키우면 된다(대신 느려진다).
- **MiniRocket을 전체 데이터로 한 번에 변환**하는 최적화는 검증 데이터의 통계를 아주 약하게 참조한다(미세한 정보 누수). MiniRocket이 정답을 보지 않는 비지도 변환이라 관례상 허용되는 수준이며, 속도 이득이 훨씬 크다. 평가를 가장 엄격하게 하려면 변환을 폴드마다 따로 하면 되지만 그만큼 느려진다.
- **CSV(녹음) 개수가 유난히 적은 클래스**가 있으면, 청크 수가 많아도 사실상 몇 안 되는 녹음에서 나온 것이라 일반화가 불안정할 수 있다. 이는 불균형 문제가 아니라 **데이터 다양성** 문제이므로, 그런 클래스는 채점표(특히 폴드 간 편차)를 더 주의 깊게 봐야 한다.
