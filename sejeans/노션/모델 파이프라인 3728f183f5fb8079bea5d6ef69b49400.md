## Notebook 1 — `모터_PNG2CSV_파이프라인.ipynb`

### 목적

AI Hub 원본 PNG(STFT 스펙트로그램, 2000×1280)를 **4피처 시계열 CSV** 로 변환합니다.
원본 대비 약 **12배 압축** (PNG 5개 15.5 MB → CSV 1개 1.3 MB).

```
INPUT_ROOT/                      OUTPUT_DIR/
  IONIQ/DEMAG/*.png    →           IONIQ/DEMAG/{group_key}__{001-005}.csv
  IONIQ/ECC10/*.png    →           IONIQ/ECC10/{group_key}__{001-003}.csv
  ...                              ...
```

### 주요 설정값

| 파라미터 | 기본값 | 설명 |
| --- | --- | --- |
| `INPUT_ROOT` | `""` | ← **필수. 원본 PNG 루트** |
| `OUTPUT_DIR` | `""` | ← **필수. CSV 저장 경로** |
| `PERCENTILE` | `90` | 활성 주파수 대역 임계치 (상위 10%) |
| `ENERGY_MODE` | `"colormap"` | `"colormap"` (jet 역변환, 권장) | `"grayscale"` (빠른 근사) |
| `ENERGY_CMAP` | `"jet"` | 원본 스펙트로그램의 컬러맵 |
| `FLIP_FREQ_AXIS` | `False` | `True` 면 주파수 bin 인덱스 상하 반전 (0=저주파로 맞출 때) |
| `KEEP_ONLY_FULLY_CONTINUOUS` | `False` | `True` 면 분할번호 끊김 없는 세션만 변환 |
| `RESUME` | `True` | 이미 만들어진 CSV 건너뛰기 (중단 후 재실행 대비) |

### 처리 흐름 (셀 순서)

**셀 3 — PNG 스캔 · 그룹핑 · 세션 분할**

`parse_filename()` 으로 파일명을 분해합니다.

```
22_07_28_12_15_20_01_zsplit005_001_Current_U.png
└──────── prefix ────────────┘ └split┘ └sensor┘
```

- `vehicle` / `fault` 는 **폴더 경로**에서 추출 (IONIQ · KONA · NIRO, DEMAG 등 폴더명 매칭)
- `sensor` 는 **파일명** 끝에서 추출 (Current_U · Vib_Motor · Vib_TM)
- `group_key` = `{prefix}_{sensor}` — 같은 연속 측정 세션의 모든 PNG가 공유하는 키
- `consecutive_runs()` 로 분할번호 연속 구간을 계산 → 구간 1개 = CSV 1개
- 분할번호가 끊기면 **별도 세션(별도 CSV)** 으로 분리하되 `group_key` 는 동일하게 유지 (학습 단계 누수 방지 호환)
- macOS `._` 숨김파일은 스캔 단계에서 제거

**셀 4 — RGB → 에너지 맵**

`load_energy_map()` 이 PNG를 `(H=1280, W=2000)` float[0,1] 에너지 2D 배열로 변환합니다.

- `ENERGY_MODE="colormap"`: jet 컬러맵 LUT를 scipy cKDTree로 역변환 → 픽셀 색 → 에너지값. 컬러 편차 없이 순수 에너지 강도만 추출.
- `ENERGY_MODE="grayscale"`: 루미넌스(`0.299R+0.587G+0.114B`). 빠르지만 jet 컬러맵에서는 근사.

**셀 5 — 4피처 추출**

`extract_features()` 가 세션 전체 에너지 맵(연속 PNG 결합)에서 시간 컬럼마다 4값을 한 번에 계산합니다(numpy 벡터 연산, Python 루프 없음).

| 피처 | 계산 방식 |
| --- | --- |
| `peak_freq` | `energy.argmax(axis=0)` — 컬럼별 최대 에너지 bin |
| `band_start` | `(energy >= 90th pct).argmax(axis=0)` — 활성 bin 최솟값 |
| `band_end` | `H-1 - mask[::-1].argmax(axis=0)` — 활성 bin 최댓값 |
| `rms` | `sqrt(mean(energy², axis=0))` — 컬럼별 에너지 크기 |

활성 bin이 없는 컬럼(조용한 구간)은 `band_start = band_end = peak_freq` 로 처리합니다.

**셀 6 — 변환 실행 및 저장**

세션별로 연속 PNG를 이어붙여 `session_to_dataframe()` 을 호출하고 CSV로 저장합니다. `RESUME=True` 면 이미 존재하는 파일은 건너뜁니다.

### 출력 CSV 스키마

| 컬럼 | 예시 | 설명 |
| --- | --- | --- |
| `group_key` | `22_07_28_..._zsplit005_Current_U` | 세션 식별자 (학습 누수 방지 키) |
| `vehicle` | `IONIQ` | 차종 |
| `fault_class` | `DEMAG` | 고장 유형 |
| `date` | `0728` | 측정 날짜 (MMDD) |
| `sensor` | `Current_U` | 센서 종류 |
| `timestamp` | `22_07_28` | 측정 시각 (YY_MM_DD) |
| `zsplit` | `zsplit005` | 정지구간 제거 번호 |
| `time_idx` | `0, 1, 2, …` | 시간 인덱스 (연속 세션 전체 기준) |
| `peak_freq` | `790` | 주파수 bin (int) |
| `band_start` | `0` | 활성 대역 시작 bin (int) |
| `band_end` | `1279` | 활성 대역 끝 bin (int) |
| `rms` | `0.7989…` | 에너지 RMS (float, 0~1) |

파일명 규칙: `{group_key}__{분할번호시작:03d}-{분할번호끝:03d}.csv`
저장 위치: `OUTPUT_DIR/{vehicle}/{fault}/` (SUBFOLDER_BY_META=True 기본)

## Notebook 2 — `모터_학습_파이프라인.ipynb`

### 목적

Notebook 1 이 만든 CSV들을 받아 **(차종 × 센서) 슬롯별** MiniRocket + LogisticRegression 모델을 학습하고, 평가 결과와 함께 `model_registry.joblib` 로 저장합니다.

```
CSV_ROOT/                        MODEL_DIR/
  IONIQ/DEMAG/...csv   →           model_registry.joblib  ← {(vehicle, sensor): model_dict}
  IONIQ/NORMAL/...csv  →           eval_results.json      ← 슬롯별 macro-F1, confusion matrix
  ...
```

### 주요 설정값

| 파라미터 | 기본값 | 설명 |
| --- | --- | --- |
| `CSV_ROOT` | `""` | ← **필수. Notebook 1 출력 CSV 루트** |
| `MODEL_DIR` | `""` | ← **필수. 모델/평가 저장 경로** |
| `CHUNK_SIZE` | `2000` | 청크 1개의 행 수 = 시계열 길이 |
| `FEATURE_COLS` | `[peak_freq, band_start, band_end, rms]` | 사용할 4채널 |
| `CLASS_ORDER` | `[DEMAG, ECC10, ECC20, NORMAL, REDUC]` | 5클래스 고정 순서 |
| `N_SPLITS` | `3` | StratifiedGroupKFold 분할 수 |
| `NUM_KERNELS` | `10000` | MiniRocket 커널 수 |
| `LR_CLASS_WEIGHT` | `None` | `"balanced"` 로 두면 클래스 가중치 자동 조정 |
| `DOWNSAMPLE` | `False` | `True` 면 다수 클래스 청크 다운샘플링 |

### 처리 흐름 (셀 순서)

**셀 2 — 데이터 유틸 정의**

세 함수를 정의합니다.

- `scan_slots()`: 모든 CSV의 첫 행만 읽어 `(vehicle, sensor)` 를 파악 → `{(vehicle, sensor): [경로 목록]}` 딕셔너리 생성
- `load_slot_chunks()`: 슬롯의 CSV들을 읽어 `(n_chunks, 4, 2000)` 3D 배열로 변환. 2000으로 나누어 떨어지지 않는 끝 행은 버림. 각 청크의 label = CSV의 `fault_class`, group = CSV의 `group_key`
- `slot_proba()`: 모델 딕셔너리와 청크 배열을 받아 항상 `(n, 5)` 5클래스 확률 반환. 슬롯에 없는 클래스는 0 채움

**셀 3 — 슬롯 스캔 실행**

```
발견된 슬롯(차종 × 센서): 3개

  IONIQ · Current_U  | CSV  80개 | 클래스 ['DEMAG', 'ECC10', 'NORMAL', ...]
  IONIQ · Vib_Motor  | CSV  80개 | 클래스 ['DEMAG', 'ECC10', 'NORMAL', ...]
  IONIQ · Vib_TM     | CSV  68개 | 클래스 ['DEMAG']   ⚠ 단일 클래스 → 분류 학습 불가(스킵 예정)
```

**클래스가 1종뿐인 슬롯은 분류가 불가능**하므로 학습에서 자동 제외됩니다. 현재 데이터가 단일 고장유형(예: DEMAG)만 있는 경우 여기서 전부 스킵 경고가 뜹니다.

**셀 4 — 모델 함수 정의**

`fit_components()` 가 하나의 슬롯을 학습합니다.

```
X(n, 4, 2000)
  └→ 채널별 표준화 (mean/std 를 instances×timepoints 축으로 계산)
       └→ MiniRocketMultivariate(num_kernels=10000)
            └→ StandardScaler
                 └→ LogisticRegression(max_iter=2000)
```

반환되는 `model_dict` 구조:

```python
{
  "ch_mean": np.array([...], shape=(4,)),   # 채널별 평균
  "ch_std":  np.array([...], shape=(4,)),   # 채널별 표준편차
  "mr":  MiniRocketMultivariate(fitted),    # 특징 변환기
  "sc":  StandardScaler(fitted),            # MiniRocket 출력 스케일러
  "lr":  LogisticRegression(fitted),        # 분류기
  "classes": ["DEMAG", "NORMAL", ...],      # 이 슬롯에서 학습된 클래스
}
```

`train_slot()` 이 슬롯 전체 학습을 관리합니다.

1. **단일 클래스 → 스킵**: 클래스 2종 미만이면 model=None 반환
2. **n_splits 자동 조정**: 클래스당 group 수가 N_SPLITS보다 적으면 가능한 수로 내림
3. **StratifiedGroupKFold 교차검증**: 각 fold에서 `fit_components` 호출 → macro-F1, accuracy, confusion matrix 수집
4. **최종 모델 재학습**: CV 완료 후 **전체 데이터** 로 `fit_components` 한 번 더 → 이것이 저장되는 배포 모델

> **데이터 누수 방지**: `StratifiedGroupKFold` 에 `groups=group_key` 를 넘겨 같은 CSV에서 나온 청크들이 train/val에 동시에 들어가지 않도록 합니다. `group_key` 는 Notebook 1 에서 이미 세션 단위로 부여되어 있습니다.
> 

**셀 5 — 전체 학습 실행**

모든 슬롯을 순회하며 학습하고 결과를 저장합니다.

```python
model_registry = {
    ("IONIQ", "Current_U"): model_dict,
    ("IONIQ", "Vib_Motor"):  model_dict,
    ...
}
```

- `model_registry.joblib`: 위 딕셔너리 전체. Notebook 3(대시보드)에서 `joblib.load()` 로 불러옵니다.
- `eval_results.json`: 슬롯별 `n_chunks`, `classes`, `n_splits`, `macro_f1_mean/std`, `acc_mean/std`, `confusion_matrix`

**셀 6 — 평가 요약 출력**

```
=== 학습된 슬롯 요약 ===
slot                n_chunks  classes  n_splits  macro_F1          accuracy
IONIQ·Current_U     1200      5        3         0.874 ± 0.021     0.891 ± 0.018
IONIQ·Vib_Motor      980      5        3         0.851 ± 0.034     0.867 ± 0.029
...
```

슬롯별 pooled confusion matrix와 per-class F1, 그리고 matplotlib 히트맵 그리드를 출력합니다.

### 출력 파일

| 파일 | 내용 |
| --- | --- |
| `model_registry.joblib` | `{(vehicle, sensor): model_dict}` — 예측에 쓰이는 모델 전체 |
| `eval_results.json` | 슬롯별 교차검증 결과 (macro-F1, accuracy, confusion matrix 등) |

## 주의사항

**데이터 요건** — Notebook 2가 의미 있게 동작하려면 슬롯당 **최소 2종 이상의 고장 클래스**가 있어야 합니다. 현재 IONIQ DEMAG 단일 클래스 데이터만 있으면 학습 단계에서 전 슬롯이 스킵됩니다. NORMAL 포함 다중 클래스 데이터를 확보해야 합니다.

**sktime 의존성** — 두 노트북 모두 sktime 설치가 필요합니다. 설치 후 import 에러 시 런타임을 재시작하고 환경 셀부터 다시 실행하세요.

**latency 측정 위치** — 단일 청크 추론 지연(≤100ms 기준)은 Notebook 2의 학습 완료 후, 대시보드 노트북의 예측 스트림 셀에서 자동 측정됩니다. 초과 시 Notebook 1의 `PERCENTILE` 조정 또는 다운샘플링을 검토하세요.
