## 3. 모터-감속기 이상 탐지 모델

### 3-1. 모델 구조 (MobileNetV2 기반 멀티태스크)

`scripts/train_motor_localizer.py` 에 학습 코드가 있습니다.

```
입력: Current_U 스펙트로그램 PNG → 224×224 리사이즈

MobileNetV2 Feature Extractor (ImageNet 사전학습)
  └─ AdaptiveAvgPool2d(1) → 1280차원 벡터

         ┌────────────────────┬───────────────────────┐
         │    분류 헤드        │    바운딩박스 헤드      │
         │  Dropout(0.3)      │  Dropout(0.3)         │
         │  Linear(1280→5)    │  Linear(1280→64)      │
         │                    │  ReLU                 │
         │                    │  Linear(64→4)         │
         │                    │  Sigmoid (0~1 정규화)  │
         └────────────────────┴───────────────────────┘
         ↓                              ↓
  분류 결과 (5개 클래스)         bbox [x1, y1, x2, y2]
```

**출력 클래스 (5종)**

| 클래스 | 의미 |
| --- | --- |
| NORMAL | 정상 |
| ECC10 | 편심(Eccentricity) 결함 10% |
| ECC20 | 편심 결함 20% |
| DEMAG | 영구자석 감자(Demagnetization) |
| REDUC | 감속기(Reducer) 이상 |

### 3-2. 학습 설정

| 항목 | 값 |
| --- | --- |
| 입력 이미지 크기 | 224×224 |
| 배치 크기 | 16 |
| 에포크 | 40 |
| 학습률 | 1e-3 (AdamW) |
| 스케줄러 | CosineAnnealingLR |
| 데이터 분할 | Train 80% / Val 20% (seed=42) |

**Data Augmentation (학습 시)**
- RandomCrop (256→224)
- RandomHorizontalFlip
- ColorJitter (밝기 ±30%, 대비 ±30%)
- ImageNet 정규화 (mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225])

### 3-3. 손실 함수

```python
loss = CrossEntropyLoss(분류) + 2.0 × SmoothL1Loss(bbox)
```

- **bbox 손실은 NORMAL 클래스에서 마스킹**: `has_box` 플래그가 0인 샘플은 bbox 손실 계산에서 제외
- SmoothL1Loss를 사용해 박스 좌표의 이상치(outlier)에 덜 민감하게 만듦

### 3-4. ONNX 내보내기 및 로딩

학습 완료 후 `export_onnx()` 함수가 `backend/weights/motor_localizer.onnx` 로 내보냅니다.

동시에 `motor_localizer_meta.json` (클래스 이름, 이미지 크기, 정규화 파라미터)도 저장됩니다.

서버 실행 시 `app/models/motor_localizer.py`의 `_try_load()` 가 ONNX 파일을 감지하면 자동 로드합니다.

ONNX 파일이 없으면 로컬라이저 기능이 비활성화되고 나머지 기능은 정상 동작합니다.

### 3-5. 이상 점수(MSE) 계산

실제 ONNX 모델이 MSE를 직접 계산하지는 않습니다.

`inference_engine.py`가 샘플의 **결함 유형 라벨**을 기반으로 현실적인 MSE 범위 내에서 랜덤하게 생성합니다.

```python
_MOTOR_SCORE_RANGES = {
    "NORMAL": (0.5,  8.0),   # 임계값(10) 이하 → 정상
    "ECC10":  (12.0, 35.0),  # 임계값 초과 → 주의/경고
    "ECC20":  (20.0, 55.0),
    "DEMAG":  (30.0, 70.0),
    "REDUC":  (25.0, 65.0),
}
_MOTOR_THRESHOLD = 10.0
```

**상태 결정 로직**

```
MSE < 10.0  → 정상 (normal)
10 ≤ MSE < 30 → 주의 (caution)
MSE ≥ 30    → 경고 (warning)
```

### 3-6. 센서 게이지 점수 생성

3개 센서(Current_U, Vib_Motor, Vib_TM)의 이상 기여도를 결함 유형에 따라 다르게 생성합니다.

| 결함 유형 | Current_U | Vib_Motor | Vib_TM | 해석 |
| --- | --- | --- | --- | --- |
| NORMAL | 2~15 | 2~15 | 2~15 | 모두 낮음 |
| ECC10 | 30~55 | 10~30 | 10~30 | 전류 이상이 주도 |
| ECC20 | 55~85 | 25~55 | 25~55 | 전류 이상 심화 |
| DEMAG | 40~70 | 50~80 | 30~60 | 진동도 함께 높음 |
| REDUC | 20~45 | 40~70 | 55~85 | 감속기 진동이 주도 |

## 4. 배터리 이상 탐지 알고리즘

모터와 달리 배터리는 **별도 신경망 없이 수식 기반 알고리즘**으로 동작합니다.

### 4-1. 입력 데이터 형식

배터리 샘플은 `(20, N)` 형태의 NumPy 배열입니다.
- **행(20개)**: 시간 스텝
- **열(N개)**: 배터리 셀 수 (IONIQ=96셀, KONA=98셀)
- 각 값: 해당 시각의 해당 셀 전압 (단위: V)

### 4-2. 배터리 메트릭 계산 (`battery_metrics.py`)

```python
cell_mean_voltages = npy.mean(axis=0)     # 각 셀의 평균 전압 (N,)
min_cell_voltage   = npy.min()            # 전체 최저 셀 전압
voltage_deviation  = npy.std(axis=1).mean()  # 셀 간 전압 편차 평균
```

### 4-3. 셀 결함 위치 탐지 (`cell_localizer.py`)

배터리 타입에 따라 두 가지 알고리즘 중 하나를 선택합니다.

**① 전압 기반 탐지 (`Vlt_96`, `Vlt_98` 타입)**

```
1. 각 셀의 20개 시점 평균 전압 계산
2. 팩 전체 평균 대비 z-score 계산: z = (cell_mean - pack_mean) / pack_std
3. 이상 점수 = clip(-z, 0) / max → [0, 1] 정규화
   (음수 z = 평균보다 낮은 셀 → 이상 점수 높음)
4. 절대 임계값(3.5V) 미만 또는 z-score < -2.0 인 셀을 불량으로 표시
```

**② 편차 기반 탐지 (`Dev_96`, `Dev_98` 타입)**

```
1. 각 셀의 20개 시점 간 표준편차(std) 계산
2. 편차의 z-score 계산: z = (cell_std - mean_std) / std_of_std
3. 이상 점수 = clip(z, 0) / max → [0, 1] 정규화
   (양수 z = 편차가 큰 셀 → 이상 점수 높음)
4. z-score > 2.0 인 셀을 불량으로 표시
```

NORMAL 상태이면 두 알고리즘 모두 건너뛰고 `cell_scores = [0.0] × N` 을 반환합니다.

### 4-4. SOH(배터리 건강도) 계산 (`soh_proxy.py`)

SOH는 세 가지 페널티 항목의 합으로 계산됩니다.

```
SOH = 100 - (W1 × deviation_norm)
          - (W2 × min_voltage_norm)
          - (W3 × anomaly_norm)
```

| 항목 | 가중치 | 정규화 기준 | 의미 |
| --- | --- | --- | --- |
| `deviation_norm` | 15점 | 최대 편차 0.10V 기준 | 셀 간 전압 불균형 패널티 |
| `min_voltage_norm` | 15점 | 정상 4.2V → 한계 3.0V 범위 | 최저 셀 전압 패널티 |
| `anomaly_norm` | 10점 | NORMAL=0, CAUTION=0.5, DEFECT=1.0 | 라벨 기반 패널티 |
- 최대 패널티: 40점 → SOH 최저값 약 60점
- 결과 범위: `[0, 100]` 으로 클리핑

### 4-5. 분류 확률 생성

라벨에서 나온 실제 분류(NORMAL/CAUTION/DEFECT)를 기반으로 현실적인 확률 분포를 생성합니다.

```python
_BAT_PROBS = {
    "NORMAL":  {"normal": (0.80, 0.98), "caution": (0.01, 0.15), "defect": (0.00, 0.05)},
    "CAUTION": {"normal": (0.05, 0.25), "caution": (0.50, 0.75), "defect": (0.05, 0.30)},
    "DEFECT":  {"normal": (0.00, 0.08), "caution": (0.05, 0.20), "defect": (0.72, 0.95)},
}
```

각 범위 내에서 uniform 랜덤 샘플링 후 합이 1이 되도록 정규화합니다.

## 5. 추론 엔진 (Inference Engine)

`app/services/inference_engine.py`의 `build_inference_response()` 가 핵심 함수입니다.

### 호출 흐름

```
build_inference_response(car_model, motor_fault, battery_status)
│
├─ get_random_motor_sample()   ← 인덱스에서 랜덤 모터 샘플 선택
│   └─ build_motor_result()
│       ├─ 결함 유형으로 MSE 점수 생성
│       ├─ 센서 게이지 점수 생성
│       ├─ 스펙트로그램 PNG URL 결정
│       └─ motor_localizer.predict(png_path)  ← ONNX 모델 호출 (있을 경우)
│
├─ get_random_battery_sample() ← 인덱스에서 랜덤 배터리 샘플 선택
│   └─ build_battery_result()
│       ├─ load_npy() → (20, N) 배열 로드
│       ├─ compute_battery_metrics()  ← 전압 통계 계산
│       ├─ localize_faults()          ← 셀 결함 위치 탐지
│       ├─ compute_soh_proxy()        ← SOH 계산
│       └─ _generate_probabilities()  ← 분류 확률 생성
│
└─ InferenceResponse 조립 (타임스탬프, 차량ID, 모터결과, 배터리결과)
```

`car_model`, `motor_fault`, `battery_status` 필터를 지정하면 해당 조건에 맞는 샘플만 선택됩니다.

## 6. WebSocket 실시간 스트리밍

`app/routers/websocket.py` — 엔드포인트: `ws://localhost:8000/ws/stream`

### 동작 방식

```
클라이언트 연결
    ↓
while True:
    1. build_inference_response() 호출
    2. alert_store.ingest_inference() → 경보 저장
    3. JSON 직렬화 → 클라이언트에 전송
    4. asyncio.sleep(2.0)  ← 2초 대기
```

- 여러 클라이언트가 동시 연결 가능 (`_connections: Set[WebSocket]`)
- 클라이언트 연결 해제 시 자동으로 집합에서 제거
- 브로드캐스트: 연결된 모든 클라이언트에 동일한 데이터 전송

### 프론트엔드 WebSocket 처리 (`hooks/useWebSocket.ts`)

```
연결 → 메시지 수신 → InferenceResult 파싱 → 상태 업데이트 → 화면 갱신
                                            → 경보 추가
                                            → 트렌드 포인트 추가
```

## 7. 경보 시스템

`app/services/alert_store.py` — 메모리 내 최대 200건 보관 (`collections.deque`)

### 경보 생성 기준

`ingest_inference(response)` 가 호출될 때마다 모터/배터리 각각 조건을 검사합니다.

**모터 경보**
- 결함 유형이 NORMAL이 아니거나 MSE > 5 이면 기록
- 레벨: normal→info, caution→warning, warning→warning

**배터리 경보**
- 분류가 NORMAL이 아니거나 SOH < 90 이면 기록
- 불량 셀 개수 포함

경보 메시지 예시:

```
Motor anomaly detected: ECC20 (score=42.3)
Battery DEFECT: SOH=68%, 3 fault cell(s)
```

### 상태 색상 결정 로직

```tsx
function computeOverallStatus(data: InferenceResult): StatusLevel {
  const levels = [data.motor.status, data.battery.status];
  if (levels.includes('warning')) return 'warning';
  if (levels.includes('caution')) return 'caution';
  return 'normal';
}
```

## 10. 모델 학습 방법

ONNX 모델이 없는 경우 아래 순서로 학습할 수 있습니다.

### 사전 조건

```bash
pip install torch torchvision onnx onnxruntime pillow numpy
```

### 학습 실행

```bash
cd dashboard/scripts
python train_motor_localizer.py
```

### 학습 과정 요약

```
1. 샘플데이터에서 Current_U 채널 PNG + JSON 라벨 수집
2. JSON에서 폴리곤 어노테이션 → bbox [x1,y1,x2,y2] 추출 (0~1 정규화)
3. 80/20 Train/Val 분할 (seed=42 고정)
4. MobileNetV2 백본 + 멀티태스크 헤드 학습 (40 에포크)
5. 최고 검증 정확도 기준으로 best.pt 저장
6. best.pt → motor_localizer.onnx 내보내기
7. motor_localizer_meta.json 저장 (클래스명, 이미지 크기, 정규화 파라미터)
```

### 출력 파일

```
backend/weights/
├── motor_localizer.onnx          ← 추론에 사용하는 모델
├── motor_localizer_meta.json     ← 클래스 이름 및 전처리 정보
└── motor_localizer_best.pt       ← PyTorch 가중치 (백업용)
```

모델 파일이 `backend/weights/motor_localizer.onnx` 경로에 있으면 서버 재시작 시 자동으로 로드됩니다.
