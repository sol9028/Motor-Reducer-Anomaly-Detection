## 0. 이번 논점

DEMAG↔NORMAL 오분류가 어디서 오는지 먼저 분리하고, 개선은 그다음에 한다.

| 가설 | 의미 | 확인 방법 |
| --- | --- | --- |
| ① 경량화 손실 | PNG를 4피처(87ch)로 줄이면서 정보가 빠짐 | 입력을 풍부하게 하면 오분류가 줄어드는지 |
| ② 모델 용량 한계 | MiniRocket+LR 자체의 한계 | 모델을 키우면 오분류가 줄어드는지 |
| ③ 데이터·라벨 한계 | 누가 해도 안 갈림 | 베이스라인도 같은 split에서 헷갈리는지 |
- 모델을 키워서 해결되면 → 경량화 방법을 바꾼다
- 우선순위: ① 기존 성능 유지 → ② 경량화

## 1. AI Hub 베이스라인: DEMAG/NORMAL 오분류 수를 공개했는가

**페이지 기준으로는 공개 안 함.**

- 공개된 수치는 모터/감속기 결함분류 성능으로 DeepLab V3+ 모델의 Accuracy 기준값 95%, 측정값 99.6%, 그리고 결함영역 탐지 mIoU 96.66%가 전부다.
- 클래스별 수치, 혼동행렬, split 방식은 페이지에 없다.
- 남은 확인처는 AI 모델 상세 설명서와 AI 모델 다운로드 파일이다(로그인 필요). **먼저 이 파일을 열어보고, 거기에도 없으면 베이스라인 코드를 돌린다.**

**이번에 찾은 중요한 사실: 라벨 규칙 자체가 센서마다 다르다.**

| 클래스 | 판정 근거 센서 (AI Hub 정의) |
| --- | --- |
| NORMAL | 라벨링이 없다는 것으로 정상 판정 |
| ECC10/20 | 모터전류와 모터진동의 라벨링 정보 |
| **DEMAG** | 모터전류 라벨링 정보만으로 감자결함 판정, 모터진동·감속기진동은 라벨링 없음 |
| REDUC | 감속기진동 라벨링 정보만으로 감속기 결함 판정 |

**의미**

- 데이터셋 정의상 DEMAG의 Vib_Motor·Vib_TM에는 "결함 표시가 없다". 즉 NORMAL과 같은 취급이다.
- 그러니 우리처럼 **센서별로 따로 5클래스를 분류하면, 진동 모델의 DEMAG↔NORMAL 혼동은 구조적으로 당연할 수 있다**(가설 ③).
- 베이스라인의 99.6%는 센서를 조합한 판정일 가능성이 크다. 이 경우 센서 단위로 비교하는 건 공정하지 않다.

**베이스라인 코드를 돌린다면 같이 봐야 할 것**

- **같은 GroupSplit**으로 돌린다. 10초 분할 조각을 랜덤 split하면 누수로 점수가 부풀 수 있다.
- **센서별 혼동행렬**과 **센서 조합 혼동행렬**을 둘 다 뽑는다.
- 600GB 전체가 아니라 **우리 split과 같은 subset**만 써도 충분하다.

## 2. 원인 분리 실험 (2×2)

|  | 작은 모델 (현재 87ch/9,996커널) | 큰 모델 (커널↑, MultiRocket 등) |
| --- | --- | --- |
| **경량 입력 (4피처)** | 현재 성능 | 여기서 좋아지면 → ② 용량 문제 |
| **풍부한 입력 (스펙트럼 대역 다채널 / PNG CNN)** | 여기서 좋아지면 → ① 경량화 손실 | 상한선(upper bound) |
- 네 칸 모두에서 진동 센서의 DEMAG↔NORMAL 혼동이 남으면 → ③ 라벨/데이터 문제로 결론, Others 공변량(토크·RPM·온도) 쪽으로 간다.
- 비교 지표는 전체 accuracy가 아니라 **센서별·차종별 DEMAG recall과 NORMAL 오경보 수**로 통일한다.

## 3. STFT 변환 시간 측정: 센서데이터를 임의로 생성해도 되나

**된다.** STFT 연산량은 입력 길이와 창 크기에만 의존하고, 신호 내용과는 무관하다.

- 입력 길이: 25,000 Hz × 10 s = **250,000 샘플**의 랜덤 노이즈로 측정한다.
- 시간축 추정: 2000 px / 10 s → **hop ≈ 125 샘플**(1 px = 1 프레임일 경우).
- "STFT 하나가 몇 초냐"의 정리:
    - PNG 1장은 **10초 구간**이다.
    - STFT 창 하나(nperseg)는 수십 ms 수준이다.
    - "1초에 변환된다"는 말은 **10초치를 변환하는 데 걸리는 연산 시간**을 뜻한다. 둘을 구분해야 한다.
- 병목은 STFT 연산(ms 단위 예상)이 아니라 **PNG 렌더링·저장**일 가능성이 크다. 두 단계를 분리해서 측정한다.
- 노이즈 이미지는 PNG 압축이 잘 안 되므로, 저장 시간은 **보수적인 상한**으로 측정된다. 발표할 때 그렇게 명시하면 된다.

## 4. 샘플링 25 kHz 과도 / 고주파 컷

**RPM 정보**

- JSON metadata에 speed 필드(예시값 3086.3231)와 temperature가 있다. 이 값이 모터 RPM일 가능성이 높다.
- 기존 확인값은 최대 RPM ≈ 5,693이다. 이 경우 회전 주파수 f_r ≈ 95 Hz이다.
- 모터는 바퀴와 1:1로 돌지 않는다. 감속기 비율만큼 더 빨리 돈다(타이어 초당 12바퀴 × 감속비).

**고주파 컷은 주의해서 해야 한다**

- 감자·편심 결함은 전기주파수 f_e = (RPM/60) × 극쌍수 근처와 그 측대역(수백 Hz)에 나타난다.
- 감속기 결함은 **기어 맞물림 주파수 = f_r × 잇수**에 나타나고, 이는 **kHz 대역**이 될 수 있다. 저주파만 남기면 REDUC 정보가 날아갈 수 있다.

**유의 대역은 추정하지 말고 데이터로 확인한다**

- 라벨 JSON의 polygon y좌표 범위(예시 y ≈ 814~1019, 높이 1280)를 **클래스×센서별로 집계**한다.
- 결함 신호가 실제로 존재하는 주파수 대역이 바로 나온다. 이 대역으로 컷 기준을 정한다.
- 대부분이 노이즈라면 대역을 뭉치는(binning) 쪽이 유리하다는 가설도 이 집계로 검증할 수 있다.
