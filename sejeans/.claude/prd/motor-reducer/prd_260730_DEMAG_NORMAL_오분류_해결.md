# PRD: DEMAG ↔ NORMAL 오분류 해결 (메타데이터 없이)

- **작성일**: 2026-07-30
- **대상**: 모터-감속기 5클래스 분류기 (`보고서/모터_학습_파이프라인_ver2.2.html`)
- **선행 문서**: `발표자료/3차발표_목차.md` (슬라이드 9·11 트랙 1)
- **제약**: `Other` 폴더 메타데이터(토크/rpm/온도 원본)는 **용량 문제로 이번 범위에서 사용하지 않음**

---

## 1. 문제 정의

3차 발표 기준 12채널 융합 모델은 macro-F1 0.826~0.874를 달성했으나,
**DEMAG(자석 감자) ↔ NORMAL(정상) 혼동이 최대 잔여 오류**로 남아 있다.

| 항목 | 값 |
|---|---|
| IONIQ Vib_TM 단일 센서 | DEMAG↔NORMAL 각 ~1,800건 상호 오분류 |
| 12채널 융합 후 | DEMAG→NORMAL 873건 (절반으로 감소했으나 여전히 최대 오류) |

이 오분류는 **안전상 가장 위험한 유형**이다. 실제 감자 고장을 "정상"으로 판정하는
False Negative이기 때문이다.

---

## 2. 근본 원인 분석 (본 PRD의 핵심)

발표자료는 이 문제를 "자석 열화의 특성"으로 서술했으나, **샘플 데이터 직접 검증 결과
원인은 물리적 난이도가 아니라 특징 추출 단계의 정보 손실**임을 확인했다.

### 원인 A — 컬러맵 역변환 누락 (치명적, 최우선)

`본격/_구버전/모터_특징추출_대용량.py:94-101`의 `image_to_energy_map()`은 다음을 계산한다.

```python
energy = np.sqrt(np.mean(arr ** 2, axis=2))   # RGB 밝기의 RMS
```

**검증 결과**: 스펙트로그램은 **jet 컬러맵**으로 렌더링되어 있다.
샘플 PNG의 최빈 색상은 `[0,0,131]`(어두운 남색, 최저 에너지)이며
`[4,205,233]`(청록) 등 jet 특유의 색이 이어진다. (unique color 1,257개)

jet 컬러맵에서 에너지↔밝기는 **단조 관계가 아니다**:

```
에너지:  낮음 ────────────────────────────► 높음
jet 색:  진한남색 → 파랑 → 청록 → 노랑 → 주황 → 진한빨강
밝기:    어두움  →  중간 → 밝음  → 최대 → 중간 → 어두움
         └────────────── 밝기가 접힘(fold) ──────────────┘
```

즉 **최저 에너지(남색)와 최고 에너지(진빨강)가 둘 다 "어두움"으로 매핑**되어
에너지 스케일의 양 끝이 서로 겹쳐진다. 소스 코드의 주석도 이미 이 위험을 지적하고
있었으나("*jet/viridis 컬러맵에서 채널 RMS는 에너지와 단조관계가 아님*") 수정되지 않았다.

**정량 확인** (IONIQ · Vib_Motor · 첫 세션):

| 방식 | NORMAL | DEMAG | 판정 |
|---|---|---|---|
| 현행(밝기 RMS) 스펙트럼 엔트로피 | 0.9826 | 0.9838 | 거의 균일 잡음 = 정보 소실 |
| 현행 16밴드 에너지 분포 | 5.5 5.4 6.7 5.7 … | 5.2 4.8 6.7 5.7 … | **두 클래스 사실상 동일** |
| **jet LUT 역변환 후** 평균 에너지 | 0.2754 | **0.3356** | 뚜렷한 차이 발생 |
| **jet LUT 역변환 후** 8밴드 에너지% | 13.45 11.78 13.95 **12.48** … | 10.71 13.09 12.57 **15.22** … | **DEMAG가 고주파로 이동** |

LUT 역변환만으로 DEMAG의 에너지가 고주파 대역으로 이동하는 패턴이 드러난다.
이는 감자 고장의 물리(기본파 약화 + 고조파 성분 증가)와 정확히 일치한다.
**현행 파이프라인은 이 판별 신호를 특징 추출 첫 단계에서 지워버리고 있다.**

### 원인 B — 4개 특징의 표현력 부족

현행 특징은 `peak_freq_bin`, `band_start`, `band_end`, `rms` 4개뿐이며,
모두 **단일 최댓값 위치 / 임계 초과 구간의 경계**만 기술한다.
DEMAG의 특징인 "고조파 대역 상대 에너지 비율"은 이 4개로 표현 불가능하다.

81개 샘플 CSV 전수 집계 결과, DEMAG와 NORMAL은 4개 특징 모두에서 겹친다:

| 센서 | 클래스 | peak_freq 중앙값 | rms 중앙값 |
|---|---|---|---|
| Vib_Motor | DEMAG | 1070.00 | 0.77 |
| Vib_Motor | NORMAL | 1047.00 | 0.74 |
| Vib_TM | DEMAG | 929.67 | 0.77 |
| Vib_TM | NORMAL | **942.50** | 0.73 |

Vib_TM에서는 DEMAG(929)와 NORMAL(942)이 **거의 동일**한 반면,
ECC10(779) · ECC20(641) · REDUC(658)은 멀리 떨어져 있다.
→ **모델이 잘 맞히는 3개 클래스는 이 4개 특징으로 분리 가능하고,
못 맞히는 2개 클래스만 분리 불가능하다.** 분류기가 아닌 특징의 문제임을 뒷받침한다.

### 원인 C — 운전 조건(rpm) 교란

`Other` 폴더 없이도 **`02.라벨링데이터` JSON(전체 1.5MB)** 에 운전 조건이 들어 있다.

```json
"metadata": { "car_model": "IONIQ", "temperature": 42.29, "speed": 2902.89 }
```

이 `speed`(rpm) 분포를 보면 DEMAG와 NORMAL이 심하게 겹친다:

| 차종 | DEMAG rpm 범위 | NORMAL rpm 범위 | 중첩 |
|---|---|---|---|
| IONIQ | 2626 ~ 2986 | 2040 ~ 3574 | **DEMAG 구간이 NORMAL에 완전 포함** |
| KONA | 2699 ~ 4107 | 2098 ~ 3201 | 광범위 중첩 |
| NIRO | 4591 ~ 5693 | 1951 ~ 3398 | 분리됨 |

현행 특징은 전부 **절대 주파수 bin 인덱스**라서 rpm이 바뀌면 그대로 이동한다.
따라서 모델은 "고장 여부"가 아니라 "회전 속도"를 학습하게 되고,
rpm이 겹치는 IONIQ·KONA에서 DEMAG↔NORMAL 혼동이 집중된다.
(발표 슬라이드 9의 "IONIQ에서 오분류 집중" 관찰과 일치)

> **핵심**: 발표자료 트랙 2가 요구한 rpm 정규화는 무거운 `Other` 폴더 없이
> **1.5MB 라벨링 JSON만으로 구현 가능**하다.

## 3. 목표 및 성공 지표

### 주요 지표

| 지표 | 현재 | 목표 |
|---|---|---|
| **DEMAG recall** (12채널 융합) | 미측정(별도 산출 필요) | **≥ 0.90** |
| **DEMAG→NORMAL 오분류 건수** | 873건 | **≤ 300건 (65%↓)** |
| macro-F1 (차종 평균) | 0.826 ~ 0.874 | **≥ 0.90** (하락 없을 것) |

### 제약 지표 (경량화 목표 유지 — 회귀 금지)

| 지표 | 현재 | 상한 |
|---|---|---|
| 단일 청크 추론 지연 | 16.5 ms | **≤ 50 ms** (목표 100ms 대비 여유 유지) |
| 융합 모델 크기 | 2.16 MB | **≤ 10 MB** |
| 전체 학습 시간 | 약 1시간 6분 | **≤ 3시간** |

> DEMAG recall을 별도 지표로 분리하는 이유: macro-F1은 5클래스 평균이라
> DEMAG 한 클래스가 나빠도 가려진다. 안전상 FN이 핵심이므로 recall을 직접 건다.

## 4. 해결 방안 (우선순위순)

### 방안 1 — jet 컬러맵 LUT 역변환 【최우선 · 필수】

**변경 위치**: `본격/모터_특징추출_v2.py` → `image_to_energy_map()`
(작성 당시 기준은 `본격/_구버전/모터_특징추출_대용량.py`. 현행 스크립트는 v2로 대체됨)

matplotlib jet 컬러맵의 256단계 RGB LUT를 만들고, 각 픽셀을 가장 가까운 LUT
인덱스로 되돌려 **실제 에너지 스칼라(0~1)** 를 복원한다.

- 구현: LUT는 256×3 배열. 픽셀별 최근접 탐색은 200k 픽셀 단위 청크 처리
  (전체 일괄 처리 시 11GB 메모리 요구 → 반드시 청크 필요)
- 사전 확인: 실제 컬러맵이 jet인지 세 센서 모두에서 검증
  (viridis/turbo 가능성 배제). 최근접 색상 잔차가 크면 컬러맵 후보를 바꿔 재시도
- **이 단계만으로 상당한 개선이 예상**되며, 이후 모든 방안의 전제 조건이다

**리스크**: 전체 CSV 재생성 필요 (600GB 본데이터 기준 재변환 비용).
→ 먼저 샘플 81 CSV로 효과를 확인한 뒤 본데이터에 적용.

### 방안 2 — 특징 확장 (4개 → 12~16개)

LUT 역변환된 에너지 맵 위에서 열(시간)별로 다음을 추가 계산한다.

| 특징 | 정의 | DEMAG 판별 근거 |
|---|---|---|
| `band_energy_1..8` | 주파수 8분할 대역별 상대 에너지 비율 | 검증에서 DEMAG 고주파 이동 확인됨 |
| `spectral_entropy` | 정규화 스펙트럼 엔트로피 | 감자 시 에너지 분산 변화 |
| `spectral_centroid` | 에너지 가중 평균 주파수 | 기본파 약화 → 중심 이동 |
| `harmonic_ratio` | 고조파 대역 / 기본파 대역 에너지비 | **감자의 직접 지표** |
| `energy_p95`, `energy_p50` | 에너지 분위수 | 밴드 임계 포화 대체 |

기존 4개는 유지하여 ECC/REDUC 성능 회귀를 방지한다.
→ 센서당 약 14채널, 3센서 융합 시 **약 42채널**.
MiniRocketMultivariate는 채널 수에 무관하게 동작하므로 코드 변경은 최소.

### 방안 3 — rpm 정규화 (라벨링 JSON 활용) 【`Other` 폴더 불필요】

`02.라벨링데이터/**/*.json`에서 `metadata.speed`(rpm)와 `metadata.temperature`를
`measure_id` 기준으로 세션에 조인한다. (전체 1.5MB — 용량 부담 없음)

두 가지 방식을 A/B 비교한다.

- **3-a (권장) 차수 정규화(order normalization)**: 주파수 축을 rpm으로 나눠
  **회전 차수(order) 기준으로 리샘플링**. 절대 Hz가 아닌 "회전당 몇 배" 축이 되어
  rpm이 달라도 같은 고장이 같은 위치에 나타난다. 원인 C를 직접 제거하는 정공법.
- **3-b (간단) 보조 채널 추가**: rpm·온도를 상수 채널로 덧붙여 모델이 조건을
  인지하게 함. 구현이 쉬우나 정규화 효과는 3-a보다 약함.

**주의**: 본데이터(600GB)에도 동일한 라벨링 JSON이 존재하는지 **먼저 확인**해야 한다.
샘플에만 있다면 이 방안은 본데이터로 확장 불가하므로, 방안 1·2를 우선 확보한다.

### 방안 4 — 2단계 계층 분류기

방안 1~3 적용 후에도 DEMAG recall이 목표에 미달할 경우에만 도입한다.

```
1단계: NORMAL vs 이상(ECC10/ECC20/DEMAG/REDUC)  — 이진
2단계: 이상으로 판정된 샘플만 4클래스 세부 분류
```

1단계에서 **DEMAG 쪽으로 임계값을 기울여** FN을 줄인다(안전 지향).
1·2단계 모두 기존 MiniRocket+LR 재사용 → 경량성 유지.

### 방안 5 — 클래스 가중치 / 결정 임계값 조정 【저비용 보조】

`LR_CLASS_WEIGHT`는 현재 `None`이다. DEMAG에 가중치를 부여하거나
DEMAG 결정 임계값을 낮춰 recall을 확보한다.
재학습 비용이 거의 없으므로 **방안 1 적용 직후 즉시 시도**할 수 있는 카드다.

> 단, 이는 precision을 희생하는 **트레이드오프일 뿐 정보를 늘리지 않는다.**
> 방안 1~2의 대체재가 아니라 미세 조정용으로만 사용한다.

## 5. 실행 순서

| 단계 | 작업 | 산출물 | 판단 기준 |
|---|---|---|---|
| 0 | 진단 재현 · DEMAG recall 베이스라인 측정 | 현행 per-class recall 표 | 개선 측정의 기준선 확보 |
| 1 | 컬러맵 검증(jet 확정) | 3센서 컬러맵 판정 결과 | 잔차 충분히 작으면 통과 |
| 2 | **방안 1** LUT 역변환 → 샘플 81 CSV 재생성 | 신규 CSV | DEMAG↔NORMAL 분리도 개선 |
| 3 | 재학습 · A/B 비교 | macro-F1, DEMAG recall | 개선 없으면 컬러맵 가정 재검토 |
| 4 | **방안 2** 특징 확장 → 재학습 | 14채널 CSV | DEMAG recall ≥ 0.90 시 조기 종료 |
| 5 | **방안 5** 가중치·임계값 튜닝 | 튜닝된 LR | 저비용이므로 병행 가능 |
| 6 | **방안 3** rpm 정규화(3-a/3-b A/B) | 조인 테이블 + 정규화 특징 | 본데이터 JSON 존재 확인 후 |
| 7 | **방안 4** 2단계 분류기 | 계층 모델 | 목표 미달 시에만 |
| 8 | 경량성 재검증 | latency·모델 크기 | 3장 상한 이내 |

**조기 종료 조건**: 어느 단계든 DEMAG recall ≥ 0.90 이면서 macro-F1 ≥ 0.90 이고
경량성 상한을 만족하면 이후 단계는 생략한다. (불필요한 복잡도 방지)

## 6. 검증 방법

- **데이터 누수 방지 유지**: 기존 `StratifiedGroupKFold` + `group_key`(세션 단위) 그대로 사용.
  방안 2·3에서 특징이 늘어도 그룹 정의는 변경하지 않는다.
- **비교 기준 고정**: 모든 A/B는 동일 `RANDOM_STATE=42`, 동일 `CHUNK_CAP_PER_CLASS`,
  동일 폴드 분할에서 수행한다.
- **필수 리포트 항목**: macro-F1뿐 아니라 **per-class recall(특히 DEMAG)**,
  **DEMAG→NORMAL 절대 오분류 건수**, latency, 모델 크기를 매 단계 함께 기록한다.
- **회귀 감시**: ECC10/ECC20/REDUC의 F1이 기존 대비 하락하지 않는지 확인한다.
