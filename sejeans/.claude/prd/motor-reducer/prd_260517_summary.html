1 문제 정의 — 직전 PRD의 Blocker

직전 v1.0 PRD는 9개 (차종 × 센서) 슬롯 × StratifiedGroupKFold(3-fold) 가정 위에서 작성되었으나, 실측 결과 group 수가 절대 부족함.

model_key DEMAG ECC10 ECC20 NORMAL REDUC
IONIQ × 3센서11214
KONA × 3센서1 ⚠21 ⚠22
NIRO × 3센서13312
즉시 실패: KONA-{DEMAG, ECC20}처럼 group 수 = 1인 클래스는 StratifiedGroupKFold(n_splits=3)에서 ValueError로 학습 자체 불가.
근본 원인: 샘플 81 CSV는 group-level stratified CV에 구조적으로 부적합 → 알고리즘 튜닝으로 해소 불가.
2 해결 전략 — 파일럿 단순화
"파일럿은 동작 검증, 성능은 본 데이터에서" 원칙 채택
① 센서별 모델 3개
Current_U / Vib_Motor / Vib_TM 분리 학습. 차종은 합쳐서 latent 변수 처리.
② Hold-out Split
GroupShuffleSplit(n_splits=1, test_size=0.2, seed=42) · stratification 포기, group 누수만 차단.
③ MiniROCKET + Ridge 유지
sktime MiniRocket(kernels=10000) + RidgeClassifierCV(balanced). 도메인 설계 승계.
④ chunk_size=2000
가변 길이 CSV를 chunk로 분할, 부모 CSV의 chunk는 동일 group_key 상속.
⑤ 단일 컬럼 'rms' 고정
36-grid search는 본 데이터 단계로 이전. 코드만 동작 검증.
⑥ 대시보드 스캐폴딩
FastAPI + Vite/TS/Tailwind 최소 화면 · 라벨/점수/model_key 표시.

결정 근거

센서 분리 (필수)
전류(Current_U) ≠ 진동(Vib_Motor/TM). 물리량·단위·스펙트럼 모두 달라 단일 모델 통합 시 Ridge 결정 경계 왜곡.
차종 비분리 (파일럿 한정)
차종 × 클래스당 group=1~4. 차종 합치면 Current_U 예시: DEMAG=3 / ECC10=6 / ECC20=6 / NORMAL=4 / REDUC=8 → min≥3로 안정.

4 시스템 아키텍처
[원천] 81 CSV (가변 길이 2000~10000) // {차종}/{고장}/{날짜}/{센서}/*.csv ↓ path_indexer + csv_loader [Sample Index] artifacts/sample_index.parquet ↓ chunker(chunk_size=2000) [Chunk Index] N ≈ 225 · 부모 CSV별 group_key 상속 ↓ sensor 필터 (Current_U / Vib_Motor / Vib_TM 각각, 차종 합산) [Per-sensor Chunk] ×3 · 센서별 부모 CSV 27개, chunk ≈ 75개 ↓ GroupShuffleSplit(n_splits=1, test_size=0.2, seed=42) ×3 [Splits] splits_{sensor}.json ×3 · assert_no_group_leakage() ↓ NaN handler + select_column('rms') + panel_formatter [Panel] (N, 1, 2000) float32 ↓ MiniRocket(num_kernels=10000) ×3 독립 인스턴스 [Features] (N, ~10000) ↓ RidgeClassifierCV(class_weight='balanced') ×3 독립 학습 [Models] pilot_current_u.joblib · pilot_vib_motor.joblib · pilot_vib_tm.joblib ↓ ModelRegistry + Dispatcher: predict(signal, sensor_name) [Inference] CSV → sensor 메타 추출 → 라우팅 → label + scores + latency ↓ FastAPI 백엔드 [Dashboard] Vite + TS + Tailwind // 라벨·점수·model_key·메타 표시
5 Pilot Success Criteria (PSC)

파일럿 단계는 성능 정량 목표 없음. 아래 6개 항목 모두 충족 시 파일럿 완료.

PSC-01
End-to-end 동작
로드 → 전처리 → 학습 → 추론 → 대시보드 단일 명령 실행, 예외 없이 완료
PSC-02
모델 저장/로드
joblib 저장 후 신규 세션 로드 → 동일 입력 → 라벨/점수 100% 일치
PSC-03
엣지 배포 형태
joblib 단일 산출물 + requirements.txt 잠금 → clean install 후 추론 성공
PSC-04
Latency 측정
measure_inference_latency()가 mean/p50/p95/p99 + 환경 메타 numeric 반환
PSC-05
Group 누수 차단
train/val의 group_key 교집합 검사 함수 존재 + 호출 + 교집합 ∅ assertion
PSC-06
스키마 호환
splits.json · config.json · registry_manifest.json 본 데이터 단계 스키마 검증
6 기대 효과 & 주요 리스크

✅ 기대 효과

블로커 해소 — StratifiedGroupKFold ValueError 우회로 파이프라인 끝까지 실행
코드 자산화 — chunker·NaN·panel·MiniROCKET·Registry·Router·Dashboard 본 데이터 단계 그대로 이전
누수 차단 사전 검증 — GroupShuffleSplit + assertion 코드가 KFold 교체 후에도 유효
학기말 발표 서사 — "feasibility 검증 완료 + 본 데이터 계획"의 명확한 학술 톤

⚠ 주요 리스크

차종 신호 차이 흡수 실패
→ 성능 평가 대상 아님 명시, 본 데이터 단계 9-모델 분리 복귀
센서별 group 분포 불균형
→ split 사후 검증, 5클래스 ≥ 1 샘플 충족까지 시드 회전(최대 10회)
단일 hold-out 평가 편향
→ 성능 평가가 목표 아님 명시, 코드 동작만 검증
chunk_size=2000 가정 변경
→ configs/preprocess.yaml 외부화, 본 데이터 첫 sweep에서 재선정
