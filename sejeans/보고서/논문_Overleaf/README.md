# Overleaf 사용 방법

이 초안은 `보고서/논문_작성_프롬프트.md`의 서론 → 이론적 배경 → 연구 방법 → 결과·논의 구조를 따릅니다. 프롬프트의 12채널 초기 결과와 이후 87채널 최종 결과를 구분해 작성했습니다.

## 가장 간단한 방법

1. `논문_Overleaf.zip`을 Overleaf의 **New Project → Upload Project**에서 업로드합니다.
2. **Compiler를 XeLaTeX**로 선택합니다.
3. **Main document를 main.tex**로 선택하고 Recompile을 누릅니다.

ZIP의 `main.tex`는 표와 그래프 데이터가 모두 들어 있는 단일 파일입니다. ZIP을 사용하지 않으려면 `paper_single.tex`의 내용을 Overleaf의 `main.tex`에 그대로 붙여 넣어도 됩니다. 외부 그림 파일, Python, BibTeX 또는 Biber 실행이 필요하지 않습니다.

## 프로젝트 폴더의 파일

- `main.tex`: 편집·관리용 LaTeX 원고. `tables/`의 자동 생성 수치를 참조합니다.
- `paper_single.tex`: 표와 그래프 데이터까지 합친 단일 LaTeX 파일.
- `main.pdf`: 로컬 XeTeX 계열 엔진 Tectonic으로 컴파일한 검토본. 빨간 확인 표시를 포함합니다.
- `tables/`: 원본 평가 JSON에서 생성한 표와 그래프 데이터.
- `verified_metrics.csv`: 구성별·차종별 점수와 오류, 원본 경로.
- `verified_summary.json`: 평균 점수, 방향별 오류 감소율 및 표본 수.
- `source_manifest.json`: 사용한 원본 평가·벤치마크 JSON의 경로와 SHA-256.
- `validation.json`: 16쪽 컴파일 및 단일 파일·분리 파일의 PDF 본문 일치 확인 기록.
- `근거_검증_및_확인사항.md`: 자료 간 차이와 미확인 항목, 주장에 적용한 제한.
- `build_tables.py`: 원본 프로젝트 내에서 `python 보고서/논문_Overleaf/build_tables.py`로 실행하면 수치표를 다시 생성합니다. 새 실험을 수행하는 스크립트는 아닙니다.

## 원고 편집

저자·소속과 최종 학회 양식은 지정되지 않아 확인 표시를 남겼습니다. 결과보고서에는 박세진·박솔이 기재되어 있지만 학술논문의 저자와 순서를 임의 확정하지 않았습니다.

`\checkneeded{...}`는 확인할 사항을 빨간 글씨로 표시합니다. 확인이 끝난 뒤 내용을 실제 값으로 바꾸세요. 확인 표시는 그대로 두어도 컴파일됩니다.

기존 세 논문의 확인된 저자·연도 및 추가 원문 출처에는 저자-연도 인용을 넣었습니다. 문헌을 찾지 못한 부분에 임의의 저자나 수치를 생성하지 않았습니다. 참고문헌은 `thebibliography` 안에서 바로 수정할 수 있습니다.

## 결과 해석에 필요한 사항

평균 Macro-F1 0.9729는 저장된 3분할 평가의 차종 평균입니다. 현행 코드는 전체 입력에 채널 표준화와 MiniROCKET을 먼저 적합하여, 완전한 폴드 내부 검증으로 재평가할 필요가 있습니다. 본 원고에는 이 제한이 본문과 초록에 반영되어 있습니다.

Pi의 455.04ms는 IONIQ 슬롯의 예열 후 표준화·변환·분류 구간입니다. STFT·LUT·특징 추출을 포함한 전체 지연은 아닙니다. 단건은 30회 측정이며 p99는 긴 실행의 최악 지연 보증이 아닙니다.

차수축 기준 회전수는 사용자가 현재 확인하기 어렵다고 답했습니다. 9,100rpm이라는 문서 기록과 5,700rpm이라는 현행 코드 기본값을 모두 적고 실제 생성 설정은 미확인으로 유지했습니다.

ZIP은 제출 확정본이 아니라 근거가 표시된 논문 초안입니다. 부록의 확인 항목을 해결한 뒤 목표 학회의 분량·양식에 맞춰 제출본을 만들 수 있습니다.
