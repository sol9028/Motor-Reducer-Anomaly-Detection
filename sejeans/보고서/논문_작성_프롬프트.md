# 논문 작성 프롬프트 — 전기차 모터-감속기 경량 고장진단

> 첨부 표(문제 제기 → 이론 배경 → 연구 방법 → 결과·논의)의 구조를 이 프로젝트에 맞춰 채운 프롬프트 모음.
> `[ ]` 안은 파라미터. **이미 채운 값은 프로젝트 문서에서 확인한 것**, `[확인 필요: …]`는 직접 채워야 하는 칸이다.

## 0. 공통 컨텍스트 (모든 프롬프트 앞에 붙여 넣기)

```
너는 공학 학술논문 작성을 돕는 조교다. 아래 연구 정보를 바탕으로 요청한 문단만 작성해 줘.

[연구 정보]
- 주제: 전기차 모터-감속기 고장을 차량 내 엣지 디바이스에서 실시간 진단하는 경량 ML 파이프라인
- 모터-감속기: 5클래스(NORMAL / ECC10 / ECC20 / DEMAG / REDUC), 차종 IONIQ·KONA·NIRO, 센서 Current_U·Vib_Motor·Vib_TM
- 입력: STFT 파생 시계열 CSV(1샘플 = 10,000 step × 수치 4컬럼: peak_freq_bin, band_start, band_end, rms)
- 모델: MiniROCKET 변환 + 선형 분류기(RidgeClassifierCV / LogisticRegression), 3센서×4컬럼 = 12채널 융합
- 엣지 검증: Raspberry Pi 4(64bit)에서 청크 1개당 추론 지연시간 측정

[작성 규칙]
- 내가 주지 않은 수치·문헌·결과는 절대 만들지 말고 [확인 필요]로 남겨.
- 학술 문어체, 한 문단 5~8문장, 주장마다 근거를 붙여.
- 인용이 필요한 자리는 (저자, 연도) 형식의 빈칸으로 표시해.
```

| 분석 방법 정당화 | [데이터 유형], [연구 질문 목적], [선택한 기법] | 장시퀀스 다채널 시계열 / 엣지 경량 분류 / MiniROCKET+선형 분류기 |

**3-1. 연구 대상 / 표본 정당화**
```
[표본 추출 방식: 확인 필요 — 예) 날짜(group_key) 단위 hold-out 분할]을 사용하여
[연구 대상 집단: IONIQ·KONA·NIRO 3차종, 5클래스, 3센서의 모터-감속기 시계열 데이터]를 선정한
[선택 이유: 같은 측정 세션의 청크가 train/test에 섞이는 데이터 누수 방지]를 설명하고,
이 방식의 한계를 보완할 [추가 조치]가 있다면 함께 명시해 줘.

[한계와 추가 조치]
- 한계: 파일럿 샘플에서 KONA-DEMAG·KONA-ECC20의 group 수가 1이라 StratifiedGroupKFold 불가
- 추가 조치: [확인 필요 — 전체 데이터(600GB) 단계에서 K-Fold 재검증 등]
```

**3-2. 데이터 수집 절차 상세 기술**
```
[자료 수집 기간: 확인 필요] 동안 [수집 도구/장비: 공개 데이터셋 출처 확인 필요, 학습 PC(Python 3.11), Raspberry Pi 4(64bit OS)]를
활용한 [구체적인 5단계 절차]를 수동태를 사용하여 객관적으로 기술해 줘.

[5단계 절차]
1. 차종·클래스·날짜·센서별 원본 CSV(10,000 step × 4 수치 컬럼)가 수집되었다.
2. 시계열이 chunk=2000 단위로 분할되었다.
3. 3센서 × 4컬럼이 12채널로 정렬·결합되었다.
4. MiniROCKET 변환 후 선형 분류기가 학습·평가되었다.
5. 학습된 모델이 Raspberry Pi 4로 이식되어 코어 수(1/2/4) × 배치(1/8/32) 조건별 지연시간이 측정되었다(온도·스로틀 플래그 동시 기록).
```

**3-3. 분석 방법 정당화**
```
[데이터 유형: 길이 10,000의 다채널 시계열, 클래스 불균형 존재]과 [연구 질문의 목적: 엣지 디바이스에서의 실시간 고장 분류]을
고려했을 때, [선택한 기법: MiniROCKET + RidgeClassifierCV/LogisticRegression]이 가장 적합한 이유를 논리적으로 설명하는 문단을 작성해 줘.
비교 대상: 수작업 76차원 특징 + SVM/RF(이전 파이프라인), YOLO 기반 이미지 분류(초기 계획).
```
